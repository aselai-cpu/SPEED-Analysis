## Ontology Design - Node Types

### 1. Event (Core Node)
**Properties:**
- eventid (UNIQUE, PRIMARY KEY)
- year, month, day
- event (Boolean - is this an actual event)
- posthoc (post-hoc reaction type)
- quasi_event (Boolean)
- coup, coup_failed (Boolean flags)

**Temporal Properties (TKG-specific):**
- valid_from: DateTime (event start)
- valid_to: DateTime (event end)
- transaction_time: DateTime (when data was recorded/coded)

### 2. Location (Spatial Node)
**Properties:**
- location_id (UNIQUE - derived from country+cowcode+gp3+gp4)
- country, cowcode
- region (8-category world region)
- gp3, gp4 (place names)
- latitude (gp7), longitude (gp8)
- loc_type (location type: densely populated, military facility, border area, etc.)

**Indexing:** Spatial index on (latitude, longitude) for geographic queries

### 3. Actor (Polymorphic Node with Labels)
**Base Properties:**
- actor_id (UNIQUE - derived composite key)
- name (actor name)
- actor_role: initiator | target | victim

**Actor Type Labels (multiple labels per node):**
- `:Actor:Group` - Insurgent, socio-cultural, or political groups
- `:Actor:Individual` - Government or non-government individuals
- `:Actor:GovernmentEntity` - Government agencies

**Group-specific Properties:**
- group_category: insurgent | sociocultural | political
- group_name (ini_igrp1, ini_sgrp1, ini_pgrp1, etc.)

**Individual-specific Properties:**
- individual_type: gov_individual | nongov_individual
- gov_level (if government)

**GovernmentEntity-specific Properties:**
- gov_level: national | subnational | local | military
- entity_type

### 4. EventType (Characteristic Node)
**Properties:**
- type_id (UNIQUE - derived)
- ev_type (Political Expression, Political Attacks, Disruptive State Acts)
- pe_type (political expression subtype)
- sym_type (symbolic event type)
- exp_type (expression type)
- atk_type (attack type)
- dsa_type (disruptive state act type)
- stat_act (state action type)

### 5. IntensityMetrics (Measurement Node)
**Properties:**
- metrics_id (UNIQUE - derived from eventid)
- n_killed_p, n_killed_a (pristine and adjusted killed count)
- n_injurd, n_injurd_d (injured counts)
- n_of_ini_p, n_of_ini_a (initiator counts)
- weapon, weap_grd (weapon types)
- pol_viol, stat_viol (violence intensity scores)
- pol_express (political expression intensity)
- mass_express (mass expression intensity)
- tang_state_repr (tangible state repression)
- intang_repr (intangible repression)
- e_length (event length)

### 6. Drivers (Causal Node)
**Properties:**
- driver_id (UNIQUE - derived from eventid)
- sc_animosity (socio-cultural animosities)
- anti_gov_sentmnts (anti-government sentiments)
- class_conflict (class-based conflict)
- eco_scarcity (ecological resource scarcities)
- pol_desires (desire for political rights)
- retain_power (desire to retain political power)
- pers_security (personal security concerns)

### 7. Outcomes (Result Node)
**Properties:**
- outcome_id (UNIQUE - derived from eventid)
- dam_prop (property damaged)
- property_damaged (type of property)
- property_owner (owner type)
- arrests (arrests made)
- victim_effect (effect on victims)
- ctry_bias (country bias in reporting)

### 8. TemporalInfo (TKG Temporal Node)
**Properties:**
- temporal_id (UNIQUE - derived from eventid)
- date_type (type of date info: precise, estimated, etc.)
- day (single day)
- jdate_pre (precise julian start date)
- jdate_pre_end (precise julian end date)
- jdate_est (estimated julian start date)
- jdate_est_end (estimated julian end date)
- ear_jdate (earliest start day)
- lat_jdate (latest end day)
- duration_days (event length in days)

**Temporal Conversion:**
- Convert Julian dates to ISO DateTime (Julian Date 0 = January 1, 1945)
- Create valid_from and valid_to timestamps

### 9. NewsSource (Provenance Node)
**Properties:**
- source_id (UNIQUE - aid)
- aid (article ID)
- news_source (NYT, WSJ, etc.)
- pub_month, pub_day, pub_year (publication date)
- code_year, code_month, code_day (coding date)
- recap (is recapitulation)

## Ontology Design - Relationship Types

### Core Event Relationships

1. **(:Event)-[:OCCURRED_AT]->(:Location)**
   - Properties: None
   - Cardinality: Many events to one location

2. **(:Event)-[:HAS_TYPE]->(:EventType)**
   - Properties: None
   - Cardinality: One-to-one

3. **(:Event)-[:HAS_INTENSITY]->(:IntensityMetrics)**
   - Properties: None
   - Cardinality: One-to-one

4. **(:Event)-[:DRIVEN_BY]->(:Drivers)**
   - Properties: None
   - Create only if at least one driver is true
   - Cardinality: One-to-one (when exists)

5. **(:Event)-[:RESULTS_IN]->(:Outcomes)**
   - Properties: None
   - Cardinality: One-to-one

6. **(:Event)-[:HAS_TEMPORAL_INFO]->(:TemporalInfo)**
   - Properties: None
   - Cardinality: One-to-one

7. **(:Event)-[:REPORTED_IN]->(:NewsSource)**
   - Properties: None
   - Cardinality: Many events to one source

### Actor Relationships

8. **(:Event)-[:HAS_INITIATOR]->(:Actor)**
   - Properties:
     - know_ini (was initiator known)
     - ambig_ini (ambiguous initiator/target)
     - ini_type (type of initiator)
   - Cardinality: One event to multiple initiators

9. **(:Event)-[:HAS_TARGET]->(:Actor)**
   - Properties:
     - tar_type (type of target)
     - tar_human_type (if human target)
     - tar_gov_type (if government target)
   - Cardinality: One event to multiple targets

10. **(:Event)-[:HAS_VICTIM]->(:Actor)**
    - Properties:
      - vic_type (type of victim)
      - vic_human_type (if human victim)
      - vic_gov_type (if government victim)
    - Cardinality: One event to multiple victims

11. **(:Actor)-[:IS_A]->(:Group|Individual|GovernmentEntity)**
    - Properties: None
    - Type: Inheritance/Classification
    - Note: In Neo4j, use multiple labels instead (e.g., :Actor:Group)

### Temporal Relationships (TKG-specific)

12. **(:Event)-[:LINKED_TO {valid_from, valid_to}]->(:Event)**
    - Properties:
      - link_type (part_of | stems_from)
      - valid_from (when link became valid)
      - valid_to (when link ceased to be valid, or null if still valid)
    - Cardinality: One-to-many (event chains/sequences)
    - Temporal Semantics: Link exists within temporal validity window

13. **(:Event)-[:REACTS_TO {valid_from, valid_to}]->(:Event)**
    - Properties:
      - posthoc (post-hoc reaction description)
      - valid_from, valid_to (temporal validity)
    - Cardinality: One-to-many
    - Created when: posthoc field indicates reaction

### Location Hierarchy

14. **(:Location)-[:CONTAINS]->(:Location)**
    - Properties: None
    - Type: Hierarchical spatial containment
    - Example: Country contains Region

## Temporal Knowledge Graph (TKG) Implementation

### TKG Principles Applied

1. **Temporal Validity:**
   - Every Event node has `valid_from` and `valid_to` timestamps
   - Relationships can have temporal validity windows
   - Support point-in-time queries: "What was the state of the graph on date X?"

2. **Temporal Evolution:**
   - Event sequences tracked via LINKED_TO relationships
   - Temporal chains show escalation patterns
   - Reaction cascades via REACTS_TO relationships

3. **Temporal Indexing:**
   - Create composite indexes on (year, month, day)
   - Range indexes for julian dates
   - Timeline indexes for temporal queries

4. **Snapshot Queries:**
   - Support queries like: "All events and relationships valid in January 2010"
   - Temporal slicing: "Show event evolution over time in Syria"

5. **Temporal Aggregation:**
   - Time-series aggregations: events per month/year
   - Sliding window analysis: intensity trends over time periods

### TKG-Specific Cypher Patterns

```cypher
// Point-in-time query
MATCH (e:Event)-[r:LINKED_TO]->(e2:Event)
WHERE e.valid_from <= datetime('2010-01-15')
  AND (e.valid_to IS NULL OR e.valid_to >= datetime('2010-01-15'))
  AND r.valid_from <= datetime('2010-01-15')
  AND (r.valid_to IS NULL OR r.valid_to >= datetime('2010-01-15'))
RETURN e, r, e2

// Temporal evolution query
MATCH path = (e:Event)-[:LINKED_TO*]->(e2:Event)
WHERE e.year = 2010 AND e.country = 'Syria'
RETURN path
ORDER BY e.valid_from
```

### Detailed Implementation Guidelines

#### 1. Constraint and Index Creation

```cypher
// Unique constraints
CREATE CONSTRAINT event_eventid IF NOT EXISTS
FOR (e:Event) REQUIRE e.eventid IS UNIQUE;

CREATE CONSTRAINT location_location_id IF NOT EXISTS
FOR (l:Location) REQUIRE l.location_id IS UNIQUE;

CREATE CONSTRAINT actor_actor_id IF NOT EXISTS
FOR (a:Actor) REQUIRE a.actor_id IS UNIQUE;

// Temporal indexes (TKG-critical)
CREATE INDEX event_temporal IF NOT EXISTS
FOR (e:Event) ON (e.valid_from, e.valid_to);

CREATE INDEX event_year IF NOT EXISTS
FOR (e:Event) ON (e.year);

// Spatial index
CREATE POINT INDEX location_coords IF NOT EXISTS
FOR (l:Location) ON (l.coordinates);

// Text indexes for search
CREATE TEXT INDEX location_country IF NOT EXISTS
FOR (l:Location) ON (l.country);

CREATE TEXT INDEX actor_name IF NOT EXISTS
FOR (a:Actor) ON (a.name);
```

#### 2. Data Cleaning and Transformation Rules

**Missing Values:**
- Empty strings ('') -> NULL
- '.' -> NULL
- NaN -> NULL
- 0 for numeric IDs -> handle as missing

**Boolean Conversions:**
- 1 -> True, 0 -> False
- "Yes"/"No" -> True/False

**Date Handling:**
- Convert Julian dates (base: Jan 1, 1945)
- Handle date_type: precise vs estimated
- Use earliest/latest for ranges

**Actor Deduplication:**
- Group actors by normalized name
- Handle name variations (fuzzy matching optional)
- Create unique actor_id from name+type+role

**Location Deduplication:**
- Deduplicate by country+cowcode
- Further deduplicate by gp3+gp4 if available
- Create location_id composite key

#### 3. Batch Processing Strategy

- **Batch Size:** 10,000 nodes/relationships per transaction
- **Memory Management:** Use APOC periodic iterate for large datasets
- **Progress Tracking:** Log progress every 10,000 rows
- **Error Handling:** Transaction rollback on error, log failed batches

#### 4. Temporal Validity Assignment

```python
def assign_temporal_validity(row: pd.Series) -> tuple:
    """
    Assign valid_from and valid_to based on date type
    """
    if row['date_type'] == 'Precise Single Day':
        valid_from = julian_to_datetime(row['jdate_pre'])
        valid_to = valid_from + timedelta(days=1)
    elif row['date_type'] == 'Precise Multi-day':
        valid_from = julian_to_datetime(row['jdate_pre'])
        valid_to = julian_to_datetime(row['jdate_pre_end'])
    elif row['date_type'] == 'Estimated Single Day':
        valid_from = julian_to_datetime(row['ear_jdate'])
        valid_to = julian_to_datetime(row['lat_jdate'])
    else:
        # Handle other date types
        pass

    return valid_from, valid_to
```

#### 5. Actor Polymorphic Node Creation

```python
def create_actor_node(tx, actor_data: Dict):
    """
    Create actor with multiple labels based on type
    """
    labels = ['Actor']

    # Determine additional labels
    if actor_data.get('group_name'):
        labels.append('Group')
    elif actor_data.get('individual_type'):
        labels.append('Individual')
    elif actor_data.get('gov_entity_id'):
        labels.append('GovernmentEntity')

    label_str = ':'.join(labels)

    query = f"""
    MERGE (a:{label_str} {{actor_id: $actor_id}})
    SET a += $properties
    """

    tx.run(query, actor_id=actor_data['actor_id'],
           properties=actor_data)
```

#### 6. Event Linkage with Temporal Validity

```cypher
// Create LINKED_TO relationships with temporal windows
MATCH (e1:Event {eventid: $from_eid})
MATCH (e2:Event {eventid: $to_eid})
MERGE (e1)-[r:LINKED_TO]->(e2)
SET r.link_type = $link_type,
    r.valid_from = e1.valid_from,
    r.valid_to = CASE
        WHEN e2.valid_to IS NOT NULL THEN e2.valid_to
        ELSE NULL
    END
```

## TKG Idiosyncrasies to Implement

1. **Temporal Validity Propagation:** When creating relationships, inherit temporal validity from source nodes
2. **Snapshot Isolation:** Support queries at specific points in time
3. **Temporal Join:** Enable joining events that overlap temporally
4. **Evolution Queries:** Track how the graph changes over time
5. **Temporal Aggregation:** Support time-windowed aggregations
6. **Bitemporal Modeling:** Distinguish between valid time (when event occurred) and transaction time (when it was recorded)
7. **Temporal Indexing:** Optimize for temporal range queries
8. **Temporal Constraints:** Ensure temporal consistency (valid_from < valid_to)

## Notes

- Julian date conversion is critical for temporal queries
- Location coordinates enable spatial queries (consider Neo4j spatial functions)

- The APOC library provides utilities for batch processing and date conversion
- Consider creating intermediate nodes for complex relationships if needed
- Use Neo4j's native datetime types for temporal properties
